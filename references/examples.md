# Liepin Fully-Automated Delivery Wizard · End-to-End Examples

> Fully shows the "user chat → config → search → delivery → result" full-chain input/output; copy to run through. All examples are real structures (desensitized).

## 1. Conversation Trigger Examples (user phrase → skill recognition)

**Scenario A: one-line start**
```
User: "Help me apply my resume to those HRD and HRBP roles on Liepin, direct hiring only, no recruiters"
→ High trigger: contains "Liepin" + "apply" + role intent + recruitment type (direct = nonRecruiter)
→ Skill: launch web wizard, pre-fill keywords, default recruitmentType nonRecruiter
```

**Scenario B: resume**
```
User: "Didn't finish yesterday, continue today"
→ Triggers resume: read historical report de-dup, apply only un-applied, daily cap still applies
```

**Scenario C: check progress**
```
User: "Any response to my applied resumes / how did it go"
→ Triggers status: read latest liepin_wizard_summary.md and report four-state result
```

## 2. Config Example (liepin_wizard_config.json)

Generated by the wizard, or hand-edited:
```json
{
  "keywords": ["HRBP", "HR Director", "HRD"],
  "industry": ["__ALL__"],
  "location": "__ALL__",
  "salaryFloor": 25,
  "salaryCeil": 500,
  "levels": ["__ALL__"],
  "recruitmentType": "nonRecruiter",
  "dailyCap": 50,
  "maxPages": 6
}
```
- `recruitmentType`: `nonRecruiter` (direct only) / `recruiter` (recruiter only) / `all` (both, non-recruiter priority)
- `__ALL__` means no restriction (works for industry / location)

## 3. Search Response Example (user-search-job)

```
Request:
POST https://open-agent.liepin.com/mcp/user
Headers: x-user-token: <JWT>, Content-Type: application/json
Body: {"jsonrpc":"2.0","id":...,"method":"tools/call",
       "params":{"name":"user-search-job",
                 "arguments":{"jobName":"HRBP","salaryFloor":"25000","page":"0"}}}

Response (after parsing, one item in data.list):
{
  "jobId": 39281745,
  "jobName": "HRBP",
  "company": "Some Tech Co., Ltd.",
  "industry": "Internet",
  "salary": "25-40k",
  "location": "Shenzhen",
  "jobType": "2"
}
```
The script then: parse salary (25-40k → floor 25 / ceil 40) → industry/location filter → recruiter detection → de-dup.

## 4. Delivery Response and Four-State Judgment Example (user-apply-job)

```
Request Body: {"name":"user-apply-job","arguments":{"jobId":39281745,"jobKind":"2"}}

① Success:
{"errCode":0,"message":"Application succeeded"} → status success

② Already applied:
{"errCode":1,"message":"You have already applied to this position"} → status already (skip, no repeat)

③ Fail (position closed):
{"errCode":500,"message":"This position is closed, cannot apply"} → status fail, reason written to report

④ Fail (401):
{"error":{"message":"unauthorized"}} → status fail, if first-item pre-check then exit code 2

⑤ Unknown:
{"result":{"content":[{"text":"{}"}]}} → status unknown, needs manual check
```
